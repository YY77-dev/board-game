# PR の下書きを作る

本スキルを実行したブランチを PR として出すための、タイトルと説明文の下書きを作る。PR そのものはユーザーが作る。

## やってはいけないこと

- PR は作成しない(`gh pr create` は実行しない)
- commit、push はしない
- merge、pull、rebase はしない。提出先の最新を取り込めていなくても、自分では取り込まない
- `work/pr/` 以外にファイルを作ったり、既存のファイルを書き換えたりしない

## 手順

コマンドは書いてあるとおりに1つずつ実行する。\
`;` や `&&` でほかのコマンドと繋げない(許可の確認が出るため)。

### 1. 提出先を決める

- 引数で指定された提出先: 「$base」
- 空なら `dev` を提出先にする。

### 2. 提出先の最新を取得する

- `git fetch origin` を実行する。
- 失敗した場合(ネットワークや認証のエラー)は、エラーの内容を伝えて終える。

### 3. 提出先が存在するか確認する

- `git rev-parse --verify --quiet origin/<提出先>` を実行する。
- 存在しない場合は、ここで止める。`git branch -r` でリモートのブランチ一覧を取得し、一覧を添えて、どのブランチに出すかをユーザーに判断を求める。

### 4. 提出先の最新を取り込んでいるか確認する

- `git rev-list --count HEAD..origin/<提出先>` を実行する。結果は、提出先にあってこのブランチにないコミットの数。
- 0 なら次へ進む。
- 1 以上なら、ここで止める。取り込めていないコミットの数を伝え、取り込まないまま下書きを作ってよいかをユーザーに判断を求め、返事を待つ。

### 5. 変更内容を集める

比べる相手は、手元のブランチではなく `origin/<提出先>` にする。

- `git branch --show-current`: 今のブランチ名
- `git log --oneline --no-merges origin/<提出先>..HEAD`: このブランチにだけあるコミット
- `git diff --stat origin/<提出先>...HEAD`: 変更されたファイル
- `git diff origin/<提出先>...HEAD`: 変更の中身

コミットが1つもない場合は、下書きを作らずに、そのことを伝えて終える。

### 6. 下書きを書く

下の「タイトルの書き方」「説明文の書き方」に従い、「雛形」の形で書く。

### 7. ファイルに書き出す

- 出力先: リポジトリ直下の `work/pr/`
- ファイル名: `YYYYMMDD_HHMMSS.md`。`date +%Y%m%d_%H%M%S` で現在時刻を取得して作る。
- 書き出したら、ファイルのパスとタイトルをユーザーに伝える。

## タイトルの書き方

- 英語で書く
- 1行に収める
- 先頭にプレフィックス(接頭辞)を付ける。複数当てはまる場合は、PR の主な変更に合うものを1つ選ぶ。

| プレフィックス(接頭辞) | 内容 |
| --- | --- |
| feat: | 新機能の追加 |
| fix: | バグ修正 |
| docs: | ドキュメントのみの変更 |
| refactor: | リファクタリング、機能に影響しない変更 |
| test: | テストコードの追加・修正 |
| style | コードの動作に影響しない書式やスペース、セミコロンなどの変更 |
| perf | パフォーマンスを向上させる改善 |
| build | ビルドシステムや外部依存関係の変更 |
| ci | CI/CD設定ファイルの変更 |
| chore: | そのた、雑務やビルドに関わらない小さな作業 |
| revert | 以前のコミットを打ち消す・元に戻す |

## 説明文の書き方

- 日本語で書く
- 見出しは「概要」「変更内容」「確認したこと」「補足」の4つ
- 確認したこと: 実際に確認したと分かることだけを書く。確認したか分からないものは推測で書かず、`- [ ]` のチェックボックスで項目だけを挙げ、ユーザーが埋められるようにする。
- 確認したこと、補足に特記事項がない場合は「特になし」と書く

## 雛形

「# タイトル」の下を PR のタイトル欄に、「# 説明文」より下を PR の説明欄に貼る。

```md
# タイトル

{タイトルを記載}

# 説明文

## 概要

{概要を記載}

## 変更内容

{変更内容を記載}

## 確認したこと

{確認したことを記載}

## 補足

{補足を記載}
```
