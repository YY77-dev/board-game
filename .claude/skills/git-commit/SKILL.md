# 変更をコミットする

本スキルを実行したブランチの変更を、そのブランチにコミットする。コミットの前に、`frontend/src` を Prettier で整形し、ESLint で自動修正する。

## やってはいけないこと

- push はしない
- ブランチの作成、切り替えはしない(`git switch`、`git checkout` は実行しない)
- merge、pull、rebase、reset、stash はしない
- `git commit --amend` で既存のコミットを書き換えない
- `--no-verify` でフックを飛ばさない
- 整形と自動修正のコマンド以外で、ファイルを書き換えない。lint のエラーも自分では直さない

## 手順

コマンドは書いてあるとおりに1つずつ実行する。\
`;` や `&&` でほかのコマンドとつなげない(許可の確認が出るため)。

### 1. ブランチを確認する

- `git branch --show-current` を実行する。
- `main` か `dev` なら、ここで止める。そのブランチに直接コミットしてよいかをユーザーに判断を求め、返事を待つ。
- 結果が空(どのブランチにもいない状態)なら、そのことを伝えて終える。

### 2. 変更があるか確認する

- `git status --short` を実行する。
- 何も出なければ、コミットするものがないことを伝えて終える。

### 3. 整形と自動修正をする

リポジトリ直下から、次の2つを順に実行する。`--dir frontend` で `frontend/` の中で実行される。

- `pnpm --dir frontend exec prettier --write src`
- `pnpm --dir frontend lint --fix`

どちらかがエラーで終わった場合は、ここで止める。エラーの内容を伝えて終える。

### 4. コミットするファイルをステージする

- `git status --short` で、手順2のあとに変わったファイルも含めて確認する。
- 手順2の時点ですでにステージされたファイルがあった場合: そのファイルだけをコミットする。整形で書き換わった分も含めるため、そのファイルをもう一度 `git add <ファイル>` する。
- 何もステージされていなかった場合: 変更されたファイルをすべて `git add <ファイル>` する。ただし、秘密の情報を含みそうなファイル(`.env`、鍵、認証情報など)は追加せず、ユーザーに確認する。
- コミットしないファイルが整形で書き換わった場合は、ステージせずに残し、最後にそのことを伝える。

### 5. 変更内容を集める

- `git diff --cached --stat`: コミットするファイル
- `git diff --cached`: コミットする変更の中身

### 6. コミットメッセージを書く

- 下の「タイトルの書き方」「説明文の書き方」に従う。
- 変更の理由は、差分やそれまでの会話から読み取れることだけを書き、推測で書かない。

### 7. コミットする

- `git commit -m '<タイトル>' -m '<説明文>'` を実行する。シングルクォートで囲み、`$` やバッククォートが展開されないようにする。
- フックなどで失敗した場合は、エラーの内容を伝えて終える。
- 成功したら `git log --oneline -1` を実行し、コミットのハッシュとタイトルをユーザーに伝える。

## タイトルの書き方

- 英語で書く
- 1行に収める。72文字以内を目安にする
- 先頭にプレフィックス(接頭辞)を付ける。複数当てはまる場合は、コミットの主な変更に合うものを1つ選ぶ。
- プレフィックスのあとは動詞の原形で始め、末尾にピリオドを付けない(例: `feat: add header navigation`)

| プレフィックス(接頭辞) | 内容 |
| --- | --- |
| feat: | 新機能の追加 |
| fix: | バグ修正 |
| docs: | ドキュメントのみの変更 |
| refactor: | リファクタリング、機能に影響しない変更 |
| test: | テストコードの追加・修正 |
| style: | コードの動作に影響しない書式やスペース、セミコロンなどの変更 |
| perf: | パフォーマンスを向上させる改善 |
| build: | ビルドシステムや外部依存関係の変更 |
| ci: | CI/CD 設定ファイルの変更 |
| chore: | その他、雑務やビルドに関わらない小さな作業 |
| revert: | 以前のコミットを打ち消す・元に戻す |

## 説明文の書き方

- 日本語で書く
- 何を変えたかと、なぜ変えたかを箇条書きで書く
- 差分を見れば分かる細かい内容(行ごとの変更など)は書かない
